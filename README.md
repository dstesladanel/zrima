# זרימה · Zrima

מערכת ניהול תורים חיה לעסקי שירות קטנים (בונות ציפורניים, ספרים, קוסמטיקאיות…). מימוש MVP (גרסה 1) של מסמך ה־PRD.
Hebrew / RTL. Node ≥ 20, **בלי תלויות חיצוניות**. הנתונים נשמרים בקובץ JSON.

## הרצה

```bash
node seed.js          # יוצר עסק דמו (מפתח בעלים: demo-owner-key)
node server.js        # http://localhost:3000
npm test              # בדיקות לחוקי המוצר
```

| כתובת | מי |
|---|---|
| `/admin` | בעל העסק: היום החי, שבוע, לקוחות, שירותים ושעות, הודעות ומבצעים, המתנה, מותג, מדיניות, מדדים |
| `/b/<slug>` | עמוד הזמנה ממותג (לביו באינסטגרם / QR) |
| `/t/<token>` | "התור שלי": סטטוס חי, אני בדרך / מאחר/ת / לא מגיע/ה, הזזה, ביטול |
| `/live/<slug>` | לוח סטטוס חי אנונימי |
| `/w/<token>` | תפיסת מקום שהתפנה (מרשימת המתנה) |
| `/o/<token>` | הסרה משיווק |

משתני סביבה: `PORT`, `BASE_URL` (לקישורים בהודעות), `DB_FILE`, `WHATSAPP_TOKEN` + `WHATSAPP_PHONE_ID` (שליחה דרך WhatsApp Cloud API; בלי זה ההודעות נרשמות ביומן בלבד).

## מה ממומש מה־PRD

- **מותג אישי** (§6): לוגו, צבעים, גופן מרשימה, טון פנייה (נקבה / זכר / ניטרלי), שם העסק בראש כל הודעה; שם המערכת רק בתחתית קטנה.
- **הזמנה** (§7): שירות → יום → שעה → שם וטלפון; זמינות לפי משך + באפר, שעות פעילות וחריגים, lead time, חלון קדימה, ביטול/הזזה עצמית עד Y שעות, זיהוי לקוח חוזר לפי טלפון, אישור אוטומטי או ידני.
- **רצפה חיה** (§8): הגיע ≠ התחיל; טיימר מתחיל רק ב"התחיל טיפול"; טבעת שקטה שהופכת ענברית רק אחרי היעד; התראת סיום; תזכורת התחלה; הארכה +5/+10/+15 עם תקרה 20 ודקות וחריגה מודעת; דחיפת כל התורים הבאים תוך ספיגה בבאפר; סיום שומר משך בפועל; Walk-in (אפשר עכשיו / עוד X דקות / אין היום) בלי לדרוס תור מאושר; הפסקה.
- **כלל הזהב**: כל שינוי בשעת כניסה של לקוח אחר יוצר הודעת תפעול (עיכוב קל ≤7, ברור 8–15, מעל 15 ממתין לאישור בעל העסק).
- **לוח חי** (§9): אנונימי (נבדק בבדיקה אוטומטית), זמן בקפיצות של 5 דקות, מיקום בתור, לקוח רואה רק את התור שלו.
- **הודעות** (§10): שני צינורות נפרדים; תפעול (נוצר, תזכורות 24ש׳/2ש׳, להתכונן, עיכובים, הקדמה, ביטול/הזזה, חור נפתח); שיווק ידני לפלחים, רק למי שנתן הסכמה, מגבלת תדירות, קישור הסרה בכל הודעה.
- **אריזת היום** (§11): זיהוי חורים; הצעות בלבד — רשימת המתנה, הקדמת לקוח עד 20 דק', הקדמת הפסקה, פתיחה להזמנה מיידית; אין הזזה אוטומטית; אחרי שתי דחיות באותו יום מפסיקים להציע.
- **כרטיס לקוח, רשימת המתנה, מדדים** (§13, §14, §17); הצעה לעדכון משך אישי אחרי 3 טיפולים (לא מוחלף אוטומטית).

## החלטות שקיבלתי איפה שה־PRD פתוח (§19)

- "אני בדרך" רק מודיע לבעל העסק, לא משנה את סדר היום.
- ביטול באיחור: ללא תשלום (אין תשלומים ב־V1). ביטול עצמי אחרי חלון המדיניות נחסם, אלא אם הלקוח נפגע מעיכוב.
- הלוח החי הכללי פתוח לכל מי שיש לו את הקישור של העסק.
- כמה כיסאות: נתמכים כנותני שירות נפרדים עם יומן נפרד (לשונית "שירותים ושעות").
- ניסוח עיכוב: קצר וחם.

## מחוץ ל־MVP / לא נסגר

אימות הבעלים הוא מפתח יחיד לכל עסק (מספיק ל־MVP; לפני הפצה כדאי OAuth/OTP).
